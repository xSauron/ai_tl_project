# Spacing & layout

## Spacing

One scale, four relations — reach for the matching semantic token before an intermediate raw step; a component with a genuinely different need gets its own component token when it's built (Stage 3), not a fifth general-purpose relation.

**Proposal flag:** the scale (4/8/12/16/24/32/48) is the design-system brief's own example. The *density split* it encodes — bed screen dense, calendar/list screens sparse, "R01 wins when in doubt" — was approved in Stage 0 (`packages/ui/POSTEP.md`). Mapping that approved decision onto these four exact numbers is this page's own proposal.
