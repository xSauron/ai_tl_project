# Color

Plant.AI has one accent idea so far: **color carries meaning, never alone** (R01.6 — the owner rejected "everything one pen color"; R02.2 — phases get separate colors). Every colored role below ships with a second signal (an icon, a border, a label) wherever it marks a state — see **What to avoid** (Stage 4) for the enforced version of this rule.

## Roles

The neutral palette (background, foreground, card, primary, muted, border…) is still shadcn's default **"neutral" base color** (`components.json`) — not yet a Plant.AI decision. No reference material picks a specific gray or warmth. Flagged for your call; not changed here (rule 12).

The calendar-phase colors below are decided (R02.2, "przyjęte") and are the first real Plant.AI color tokens.

## Domain colors not built yet

Two domain-color groups named in the design-system brief have **no token yet**, on purpose:

- **Good/bad companion neighbors** (grid screen) — grounded in R04 and `2026-10-20-garden-grid.md` ("conflicting ones get a `CompanionBadge` outline"), but the actual color + the required second signal (the spec says *outline*, not fill) belongs with the `CompanionBadge` component itself. Building it here, ahead of the component, would guess at a value the component doesn't need yet. Planned for Stage 3.
- **Grid cell states** (empty / occupied / selected / AI-preview) — same reasoning; "AI proposal preview" is additionally out of scope entirely right now (D08/D09, Later — see `packages/ui/POSTEP.md`).

## Threshold

WCAG AA: **4.5 : 1** for text, **3 : 1** for UI-element boundaries (approved in Stage 0 — not raised for the sun/phone context; see `packages/ui/POSTEP.md`). Any pair below threshold is flagged inline above, never silently shipped.
