# Backward compatibility

This document inventories Plant.AI's protected contract surfaces as they exist today and the required path for changing each one. Review skills (`om-code-review`, `om-auto-review-pr`) check PRs against it; implementation skills warn when a change is not compliant. Update this file in the same PR that adds, removes, or changes a surface listed here — a surface the repo doesn't have yet is not listed until it exists.

The repo is at the bootstrap stage (see the migration table in `AGENTS.md`): these are today's actual surfaces, not the target architecture. Re-run `om-setup-agent-pipeline` (or hand-edit this file) as new concepts land.

## HTTP routes (`packages/app/src/app/api/`)

| Route | Contract | Breaking change | Required path |
|---|---|---|---|
| `GET /api/health` | Runs a real `select 1` via `checkDbConnection()`. Returns `200 { status: "ok", db: { ok: true } }` or `503 { status: "error", db: { ok: false, reason: string } }`. | Changing the status codes, the `status`/`db` field names, or `db.ok`'s boolean meaning. Removing the real DB round-trip (the route exists specifically so uptime checks and `AGENTS.md`'s "`/api/health` must keep working" rule have a real signal). | Keep the shape additive (new optional fields only); a breaking change needs a version bump in the path (`/api/v2/health`) or an explicit deprecation window announced in the PR body, plus updating every consumer (currently none outside ops tooling). |
| Envelope + CSRF (every route below, `core/src/http/apiHandler.ts`) | JSON `{ ok: true, data }` or `{ ok: false, error: { code, message, fieldErrors?, details? } }`; clients switch on the stable `code`, never on `message`. Every method except `GET`/`HEAD` needs `x-plantai-request: 1` (403 `CSRF_REJECTED`); `ui`'s `apiCall` always sends it. Every response carries `x-request-id`; 429s carry `Retry-After`. | Renaming or removing an error `code`, changing the envelope keys, or dropping the CSRF check. | Add codes freely; a renamed code needs every `ui`/app consumer updated in the same PR. The CSRF header value is pinned by `tests/contracts/csrf-header.test.ts`. |
| `POST /api/auth/register`, `POST /api/auth/login` | Public, `{ email, password }` (`registerSchema` / `loginSchema`), rate-limited per normalized e-mail (+ trusted IP). 201 / 200 `{ user: { id, email, isEmailVerified } }` plus the `plantai_session` cookie (`HttpOnly; SameSite=Lax; Path=/; Max-Age=86400`, `Secure` in production). Errors: 422 `VALIDATION_FAILED` / `REGISTRATION_FAILED` (generic, also for a taken e-mail), 401 `INVALID_CREDENTIALS` (generic), 429 `RATE_LIMITED`. | Revealing whether an e-mail exists, renaming the cookie, or weakening its flags. | Cookie or flag changes ship with a note in the PR body (every signed-in user is logged out by a rename). |
| `POST /api/auth/logout`, `GET /api/auth/me`, `POST /api/auth/password` | Session required (401 `UNAUTHORIZED` otherwise). Logout clears the cookie; `me` returns `{ user }` (401 for a deleted account); `password` takes `{ currentPassword, newPassword }`, answers a wrong current password with 422 `fieldErrors.currentPassword`, and is rate-limited per user. | Changing these shapes or codes. | As above. |
| `GET, POST /api/gardens`, `GET, PATCH, DELETE /api/gardens/[id]` | Session required. Bodies: `gardenCreateSchema` (`name` 1–120, `description` ≤ 2000 or null, unknown keys rejected) and its `.partial()` for PATCH. List: the caller's gardens, newest first; POST 201 `GardenDto`, 409 `LIMIT_REACHED` past 20; DELETE `{ id }`. Another user's garden is 404 `NOT_FOUND`, identical to a missing one. | Letting a foreign id read differently from a missing one, accepting unknown keys, or changing `GardenDto`'s fields. | Additive `GardenDto` fields are fine; anything else needs the app pages updated in the same PR. |

As `api/<concept>/route.ts` handlers are added per the domain-invariants section of `AGENTS.md`, each row here gets: the JSON envelope shape (`{ ok: true, data }` / `{ ok: false, error: { code, message, fieldErrors? } }` once `core/src/http/apiHandler.ts` exists), the request schema, and the auth/ownership requirement.

## Server Actions

None. **Removed on 2026-11-03** (app-primitives 5.1): `createGardenAction` and the `/admin/gardens` page. They listed and created every user's gardens without a session, which ownership (spec A) can't allow; gardens are managed by their owners through `/api/gardens` and the `(app)/gardens` page. This was the deliberate breaking change this section anticipated. Client writes go through `apiCall` → `/api/*` only (AGENTS.md), so no Server Action replaces it.

## Workspace package names (`packages/*/package.json`)

| Surface | Contract | Breaking change | Required path |
|---|---|---|---|
| Package scope `@plantai/*` (`@plantai/app`, `@plantai/core`, `@plantai/db`, `@plantai/ui`) | Every workspace import specifier (`@plantai/core`, `@plantai/ui/components/ui/*` for shadcn primitives, `@plantai/ui/components/*` for concept components, `@plantai/ui/styles.css`), every root script's `-w @plantai/<name>`, and the shadcn aliases in `packages/ui/components.json` use this scope. | Renaming the scope or a package. **Done once on 2026-11-03** (app-primitives 0.2, standards §5 step 1): `@plant-ai/*` → `@plantai/*`. Any local branch or tool still importing `@plant-ai/*` or running `npm … -w @plant-ai/<name>` breaks and must switch to `@plantai/*`; re-run `npm install` so `node_modules/@plantai/*` links replace the old `node_modules/@plant-ai/*` ones. **Primitive paths moved on 2026-11-03** (app-primitives 3.1): `@plantai/ui/components/<primitive>` → `@plantai/ui/components/ui/<primitive>` (`badge`, `button`, `card`, `input`, `label`, `separator`, `table`); every in-repo import was updated in the same commit. | Rename every `package.json` `name` and dependency, import, script, config alias and doc in the same PR, regenerate `package-lock.json`, and call the rename out in the PR body. The packages are private (not published), so there is no external consumer or deprecation window. |
| Persistence package `@plantai/db` (`packages/db`) | Owns entities (`src/entities/<concept>/`), migrations + `.snapshot-*.json` (`src/migrations/`), the ORM config, `getOrm()`/`closeOrm()`/`checkDbConnection()` and the DB env vars. **Moved once on 2026-11-03** (app-primitives 0.3, standards §5 step 2) from `packages/core/src/{entities,migrations,db,mikro-orm.config.ts,config/env.ts}`; migration names and the `mikro_orm_migrations` table are unchanged, so already-applied migrations stay applied. | Moving these again or renaming a migration. Branches that added files under the old `packages/core/src/entities/` or `migrations/` must move them to `packages/db/src/…` and run `npm install` to link `@plantai/db`. | `@plantai/core` keeps re-exporting the same names (below), so `@plantai/app` imports don't change. |

## `@plantai/core` package exports (`packages/core/src/index.ts`)

Everything re-exported here is the public surface other workspaces (`@plantai/app`) are allowed to import; anything not exported here is internal to `core` even if the file is technically reachable.

| Export | Contract | Breaking change | Required path |
|---|---|---|---|
| `getOrm()`, `closeOrm()`, `checkDbConnection()`, `DbConnectionStatus` | `checkDbConnection()` resolves `{ ok: true }` or `{ ok: false, reason: string }`, matching the `/api/health` response above — the route's contract and this type must change together. `getOrm()`/`closeOrm()` manage the per-layer ORM instance (see `.ai/lessons/2026-10-13-mikroorm-next-layers.md` — never cached on `globalThis`). | Changing the `DbConnectionStatus` shape, or making `getOrm()` return a cached global instance. | Update `/api/health` and the admin dashboard (`(admin)/admin/page.tsx`) in the same PR; note the MikroORM-layer caveat from the linked lesson. |
| `getContainer()`, `withScope(fn)`, `AppContainer`, `AppCradle`, `RequestScope`, `RequestCradle` types | The Awilix DI surface (`core/src/container/{container,cradle,scope}.ts`): `withScope(fn)` must keep running `fn` in a fresh scope with a forked `EntityManager` per request and disposing it in `finally`, matching `AGENTS.md`'s "Never cache the ORM or container on `globalThis`" rule. `AppCradle`/`RequestCradle` name every resolvable service. | Removing a cradle key a page already resolves (e.g. `gardenService`), or changing `withScope()` to share an `EntityManager` across requests. **Changed once on 2026-11-03** (app-primitives 0.4, standards §5 step 2): `createRequestScope()` is no longer exported and `@plantai/app`'s internal `withRequestScope` (`app/src/server/request-scope.ts`) became `withScope` from `@plantai/core`; branches calling either must switch to `withScope`. | Add new cradle keys freely (additive); removing or renaming one needs every consumer in `packages/app` updated in the same PR, and the DI rules in `AGENTS.md` kept in sync. |
| `GardenService`, `CreateGardenInput`, `UpdateGardenInput` | A `CrudService` for one actor: `list(actor)` (the actor's gardens, `createdAt: "desc"`), `get(actor, id)`, `create(actor, input)` (409 `LIMIT_REACHED` past `MAX_GARDENS_PER_USER`, counted under a lock on the user row), `update(actor, id, input)`, `remove(actor, id)`; all return `GardenDto`s and answer a missing or foreign id with 404 `NOT_FOUND`. **Changed on 2026-11-03** (app-primitives 5.1): `list()`/`create(input)` took no actor and returned all rows. | Dropping the actor argument, returning entities, or letting a foreign id read differently from a missing one. | Widen the inputs freely; narrowing one needs every caller (`api/gardens` routes) updated in the same PR. |
| Entity and ORM re-exports from `@plantai/db` (`entities`, `Garden`, `getOrm`, `closeOrm`, `checkDbConnection`) | See DB schema below — entities are re-exported as-is, so their contract is the DB schema's contract. | See DB schema below. | See DB schema below. |

Future ports/adapters (`AiGateway`, `ImageStorage`, `FrostDateProvider` — not yet present) join this table once they exist; the adapter implementation (`MockAiGateway` vs. a real vendor SDK) is explicitly *not* part of the contract — only the port interface is.

## Database schema & migrations (`packages/db/src/entities/`, `packages/db/src/migrations/`)

| Surface | Contract | Breaking change | Required path |
|---|---|---|---|
| `base.entity.ts` shared columns (`id: uuid primary`, `createdAt`, `updatedAt`) | Every entity gets a random UUID primary key and audit timestamps (`timestamptz`, set on create/update). | Changing the primary key type, making `id` client-settable, or dropping `createdAt`/`updatedAt` from an entity that has them. | Any column removal or type change on an existing table ships as a migration with an explicit up/down pair; never edit a merged migration (`AGENTS.md`). |
| `Garden` entity (`gardens/garden.entity.ts`, table `gardens`) | Columns: `name` (`varchar(120)`, required), `description` (`text`, nullable), `owner_id` (`uuid`, not null, → `users.id` `on delete cascade`, indexed), plus the base columns above. **Changed on 2026-11-03** (migration `add_garden_owner`): the migration deletes every existing row (ownerless demo data) before adding `owner_id`; its `down` can't restore them. | Shrinking `name`'s length below what existing rows may contain, making `description` non-nullable, making `owner_id` nullable, or renaming/dropping a column without a migration. | Generate a migration (`npm run db:migrate:create -- --name <slug>`), commit the migration **and** its `.snapshot-*.json`, and review the SQL for data loss on existing rows. |
| `User` entity (`auth/user.entity.ts`, table `users`, added 2026-11-03) | Columns: `email` (`varchar(254)`, unique, stored trimmed and lower-cased), `password_hash` (`varchar(100)`, bcrypt over a SHA-256 pre-hash), `email_verified_at` (`timestamptz`, nullable), plus the base columns. | Changing the hashing scheme without a rehash-on-login path (existing passwords would stop verifying), storing e-mails un-normalized, or exposing `password_hash` in a DTO. | Migration as above; a hashing change ships with verification of the old format.
| `Migration20261013192505_init.ts` and every future migration file | Migrations are append-only history; MikroORM replays them in order against every environment including CI's ephemeral Postgres. | Editing, renaming, or deleting a migration that has already been merged to `main`. | A mistake in a merged migration is fixed by a **new** forward migration, never by editing the old one — per `AGENTS.md`'s persistence rules. |

As more entities and concepts (`plantings`, `crops`, `calendar`, `journal`, `photos`) land, each gets a row here, plus the domain invariants from `AGENTS.md` that constrain their schema (e.g. beds use optimistic locking via a `version` column; calendar dates are date-only `YYYY-MM-DD`, never `timestamptz`).

## Config file formats

| Surface | Contract | Breaking change | Required path |
|---|---|---|---|
| `.env.example` / `db/src/env.ts` (`DATABASE_URL`, `DB_POOL_MIN`, `DB_POOL_MAX`, `DB_DEBUG`) / `core/src/config/env.ts` (`JWT_SECRET`, `LOG_LEVEL`, `NODE_ENV`) | Every documented variable is read through a lazily parsed, Zod-validated `env.ts` (per `AGENTS.md`); `.env.example` is the source of truth for what must be set, and the app must still build with no env and boot with no database reachable. Since app-primitives 1.1 (2026-11-03) malformed DB values (`DB_POOL_MAX=10abc`, `DB_DEBUG=yes`, `DB_POOL_MIN` > `DB_POOL_MAX`) throw instead of being silently coerced. | Renaming or removing a documented env var without a fallback/migration note, or making a previously-optional var required without a default. | Add new vars to `.env.example` with a comment in the same PR that starts reading them; a rename keeps the old name working for one deprecation window or documents the cutover explicitly in the PR body. |

## Package manager scripts (root `package.json`, workspace `package.json`s)

| Surface | Contract | Breaking change | Required path |
|---|---|---|---|
| `npm run db:migrate`, `db:migrate:create -- --name <slug>`, `db:migrate:down` | Thin wrappers over the MikroORM CLI (`mikro-orm migration:up/create/down`) scoped to `@plantai/db` (`-w @plantai/core` until 2026-11-03); documented in `AGENTS.md`'s Commands table. | Changing a script's name, its required flags, or which workspace it targets, without updating `AGENTS.md` and `SDLC.md`'s validation gate in the same PR. | Treat these as a CLI surface: keep flag compatibility or document the new invocation everywhere it's referenced (`AGENTS.md`, CI, this file). |
| `npm run typecheck`, `lint`, `test`, `build`, `test:integration` | The validation gate every PR passes (`SDLC.md`); `test` enforces 100% coverage via `vitest.config.ts`. | Changing what counts as passing (e.g. lowering the coverage threshold, dropping a workspace from `--workspaces --if-present`) without updating `SDLC.md`'s Validation gate section and `.ai/agentic.config.json`'s `validation.commands` together. | Update `SDLC.md`, `.ai/agentic.config.json`, and `.github/workflows/ci.yml` in the same PR as any gate change. |

## Not yet present

No published events/webhooks exist yet (`core/src/events`, per `AGENTS.md`'s migration table — "not yet present"), no `auth` concept, and no AI ports/adapters. When any of these land, add a section here in the same PR, inventorying the actual contract (event ID naming `concept.entity.action`, port interfaces, etc.) rather than the target design — this file always describes what exists, not what's planned.
